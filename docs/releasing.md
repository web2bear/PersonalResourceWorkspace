# Выпуск версий

Проект использует GitHub Actions workflow [`Build, Test & Release`](../.github/workflows/release.yml).

## Формат первой версии

Публикуется предварительная версия для Windows x64: переносимый ZIP с приложением и зависимостями, а также файл SHA-256 для проверки загрузки. Это **не установщик**. Архив не подписан цифровой подписью; для подписывания потребуется отдельный сертификат и настройка безопасного хранения ключа.

## Проверка перед выпуском

Каждый push в `main` и каждый pull request запускает сборку, тесты и публикацию x64 ZIP в артефакты Actions. Только успешная сборка может перейти к GitHub Release. CI проверяет наличие исполняемого файла в опубликованном каталоге. Отдельный запуск приложения на чистой Windows машине остаётся ручной проверкой перед объявлением версии готовой для пользователей.

## Создать релиз

1. Убедитесь, что последний запуск workflow на `main` завершился успешно, включая задание **Publish Windows x64**.
2. Откройте **Actions → Build, Test & Release → Run workflow**.
3. Выберите ветку `main`, задайте свободный номер версии, например `0.1.2`, без префикса `v` и включите **Create a prerelease**.
4. После завершения проверьте раздел **Releases**: новый тег, ZIP, файл `.sha256` и описание.
5. Распакуйте ZIP целиком на Windows x64, запустите `PersonalResourceWorkspace.App.exe` и проверьте открытие окна и основные сценарии.

Тег `v0.1.0` указывает на коммит до исправлений workflow; первый опубликованный prerelease — [`v0.1.1`](https://github.com/web2bear/PersonalResourceWorkspace/releases/tag/v0.1.1). Не перезаписывайте существующие теги: для следующего выпуска выбирайте новый номер.

Для выпуска через новый тег вместо ручного запуска создайте тег от проверенного коммита `main` и отправьте его на GitHub. Workflow также создаст предварительный релиз.
