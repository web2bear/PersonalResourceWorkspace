# 03 — Перенести политику удаления в Application

**Приоритет:** P2. **Статус:** ready-for-agent.

**Что сделать:** удаление ресурса, очистка корзины и удаление коллекции выполняются Application-сценариями с едиными правилами. UI получает сведения для подтверждения, передаёт подтверждённое намерение и отображает результат.

**Блокируется:** ничем — можно начать сразу.

**Граница:** политика корзины, защита системных коллекций, выбор допустимой fallback-коллекции и атомарное исполнение через persistence-порты. Текущие строковые представления membership допустимы до задачи 04. Диалоги остаются presentation-owned; Application не зависит от ContentDialog. Защитные проверки persistence можно сохранить как защиту целостности, но не как единственное место политики.

**Критерии приёмки:**

- [ ] Обычный ресурс перемещается в корзину; ресурс в корзине удаляется окончательно только после соответствующего подтверждения.
- [ ] Отмена подтверждения не выполняет записи.
- [ ] Default-коллекцию и корзину удалить нельзя независимо от точки входа.
- [ ] Отсутствующий либо недопустимый fallback даёт явный результат без изменения БД/UI.
- [ ] Изменённое между подтверждением и исполнением состояние проверяется повторно; небезопасная операция отклоняется.
- [ ] Ошибка persistence не публикует успешное UI-state; многострочные изменения выполняются транзакционно.
- [ ] Правила проверяются через fake-порты без WinUI/SQLite; адаптер проверяется отдельно.

**Решение для непустой коллекции:** PROJECT.md требует выбора отмена/каскад, текущий UI предлагает перенос в fallback. Для соответствия контракту реализовать явный каскад с отдельным подтверждением; перенос при необходимости оставить отдельным явно обозначенным действием. Не допускать скрытого изменения политики или неявной потери содержимого. Будущее дерево вложенных коллекций в эту задачу не входит.

**Проверка:** таблица сценариев удаления/отмены/защиты/ошибок в Application-тестах; SQLite rollback; build и ручные проверки диалогов.
