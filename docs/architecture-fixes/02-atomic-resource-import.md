# 02 — Сохранять добавляемый пакет ресурсов атомарно

**Приоритет:** P2. **Статус:** ready-for-agent.

**Что сделать:** drag/drop нескольких ресурсов сохраняет весь пакет одной транзакцией; только после commit появляются карточки и сообщение об успехе. Сейчас UI меняется до сохранения, а SaveResourcesAsync записывает весь workspace отдельными вызовами.

**Блокируется:** ничем — можно начать сразу.

**Граница:** Application-сценарий добавления и порт пакетного сохранения, SQLite-транзакция, соответствующие входы UI. Существующий SaveAsync сохранить для одиночных изменений. Схему, идентификатор коллекции и политику удаления не менять. Метаданные visual сохранять с пакетом; необязательный auto visual запускать после commit, его ошибка не отменяет успешно созданные ресурсы.

**Критерии приёмки:**

- [ ] Сохраняется только новый пакет, существующие ресурсы не перезаписываются.
- [ ] Ошибка на втором элементе откатывает весь пакет; до commit карточки не публикуются.
- [ ] Отмена до commit не оставляет частично записанных ресурсов.
- [ ] Успех добавляет каждую карточку ровно один раз; пустой пакет не выполняет записи.
- [ ] Повторный drop сохраняет действующую защиту от дубликатов.
- [ ] Ошибка auto visual после commit оставляет ресурсы доступными с fallback.
- [ ] Все входы добавления используют согласованную операцию; необязательных изменений редактора и удаления нет.

**Проверка:** isolated SQLite с детерминированной ошибкой второй записи и проверкой rollback; Application-тесты результата; build App и ручной drop нескольких файлов.
