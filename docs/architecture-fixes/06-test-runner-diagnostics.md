# 06 — Получить воспроизводимый результат тестового запуска

**Приоритет:** проверка. **Статус:** ready-for-agent.

**Что сделать:** установить причину сбоя тестовой инфраструктуры и документировать рабочий запуск Domain/Application/Infrastructure suites. Обзор не подтвердил прохождение тестов: Application-run с blame завершился таймаутом подключения datacollector за 90 секунд.

**Блокируется:** ничем — можно начать сразу; проверки других задач могут разрабатываться параллельно.

**Граница:** тестовый runner, конфигурация окружения и документация запуска. Не менять production-код, не отключать проверки поведения ради успешного отчёта и не считать таймаут доказательством дефекта приложения.

**Критерии приёмки:**

- [ ] Отдельно проверены обычный запуск без collector/blame и запуск с диагностикой; сохранены команды, exit code и краткая причина различия.
- [ ] Получены реальные результаты трёх suites с количеством пройденных/проваленных тестов, либо точное воспроизводимое ограничение среды.
- [ ] Если нужны изменения конфигурации, они минимальны и обоснованы установленной причиной; простое увеличение timeout не выдаётся за исправление причины.
- [ ] SQLite suites используют временные app-data roots; пользовательская БД не затронута.
- [ ] Документирован способ запускать целевые проверки для задач 01–05.

**Проверка:** повтор рабочего запуска; сборка изменений и runtime UI остаются обязанностью каждой задачи, затрагивающей приложение.
