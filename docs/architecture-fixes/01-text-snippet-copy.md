# 01 — Копировать TextSnippet вместо открытия через shell

**Приоритет:** P1. **Статус:** ready-for-agent.

**Что сделать:** default action текстовой заметки копирует сохранённое содержимое в системный clipboard и показывает результат пользователю. Сейчас ResourceLaunchService передаёт текст в OpenPathAsync.

**Блокируется:** ничем — можно начать сразу.

**Граница:** обработка TextSnippet в Application, отдельный порт записи текста, Windows-адаптер, DI и обратная связь UI. Существующий порт чтения clipboard и формат хранения сохранить. Внутри операции использовать явное представление текстового содержимого; глобальную миграцию payload всех типов не проводить. Web/File/Folder/Application сохранить. Полную систему действий Command/Collection/ImageSnippet здесь не реализовывать.

**Критерии приёмки:**

- [ ] Открытие заметки из карточки, клавиатуры и меню выполняет Copy через единый сценарий.
- [ ] Сервис передаёт сохранённую строку без дополнительного Trim, включая переводы строк и пробелы; изменения редактора содержимого вне объёма.
- [ ] Fake-shell не получает вызовов для TextSnippet; fake-clipboard получает один вызов.
- [ ] Ошибка записи clipboard отображается как ошибка действия, без сообщения об успехе и shell fallback.
- [ ] Отмена до действия не меняет clipboard; Web/File сохраняют проверенное поведение.
- [ ] Application-тесты не требуют WinUI; на Windows вручную проверены Copy/Paste и обратная связь.

**Проверка:** тесты ResourceLaunchService с fake-портами, build App, реальное открытие заметки и вставка в текстовый редактор.
