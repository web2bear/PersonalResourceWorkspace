# Переход от коллекций к тэгам: решения обсуждения

Статус: согласованная модель, реализуемая в текущей ветке. Поведение приложения проверяется отдельно от этого документа.

## Принятые решения

- Ресурс может иметь несколько тэгов. В первой версии тэг не имеет цвета и иконки; визуальные атрибуты принадлежат только сохранённому поиску. Цвет тэга может быть рассмотрен в будущей версии.
- Боковая панель показывает дерево именованных сохранённых поисков, а не иерархию тэгов. Каждый узел содержит собственное имя и набор условий. Поиск по одному тэгу — частный случай.
- Сохранённый поиск содержит набор обязательных тэгов, объединённых условием «И». Сохранённая текстовая строка и другие фильтры в первую версию не входят.
- Новый пользовательский поиск создаётся только кнопкой «Сохранить поиск» рядом с полем поиска. Действия «закрепить тэг» в карточке нет.
- Кнопка «Сохранить поиск» создаёт новый узел из текущих условий. Временные условия не изменяют выбранный поиск; его условия меняются только через отдельное «Редактировать поиск».
- При сохранении объединяются тэги выбранного поиска и временные тэги; текстовый запрос не включается. Перед подтверждением показывается итоговый набор и пояснение, что сохраняются только тэги.
- При переходе к другому узлу панели временные тэги и текстовый запрос очищаются.
- Временные тэги показываются отдельными удаляемыми чипами рядом с текстовым вводом; обязательные тэги выбранного поиска показываются отдельно как постоянная основа результата.
- В редакторе ресурса ввод имени показывает существующие тэги; Enter создаёт отсутствующий тэг и назначает его ресурсу. Сравнение имён игнорирует регистр и пробелы по краям.
- При создании ресурса из пользовательского поиска редактор предварительно назначает тэги этого поиска и временные тэги из поля поиска. Из обязательного поиска «Входящие» назначается «Входящие»; из «Корзины» создание отключено.
- Если условия поиска содержат «Входящие» вместе с пользовательскими тэгами, новый ресурс получает их все: явные условия поиска имеют приоритет над автоматическим снятием «Входящих». Создание отключено в любом поиске с условием «Корзина».
- Имена разных сохранённых поисков могут совпадать; каждый поиск имеет собственную устойчивую идентичность.
- Переименование тэга сохраняет его связи с ресурсами и условия сохранённых поисков, которые ссылаются на устойчивую идентичность тэга.
- Текстовый запрос сочетается с обязательными тэгами выбранного поиска и временными тэгами по правилу «И». Текст и временные тэги не сохраняются автоматически.
- Вложенность узлов влияет только на отображение панели. Дочерние поиски не расширяют результат родителя. Перемещение узла не меняет результаты поиска и тэги ресурсов.
- Удаление родительского поиска удаляет из панели всё его поддерево после предупреждения с числом дочерних поисков. Это не меняет тэги и связи ресурсов.
- Только «Корзина» и «Входящие» — предопределённые неудаляемые тэги и обязательные закреплённые поиски. Их поиски находятся на верхнем уровне, их можно переставлять, но нельзя вложить или удалить.
- Условия обязательных поисков не редактируются: каждый ищет по одноимённому системному тэгу. Их оформление и порядок на верхнем уровне можно менять.
- «Избранное» не является системным тэгом или поиском. Если пользователь создаст такой тэг, он будет обычным. Явные операции со звездой и состоянием избранного убираются из целевой модели.
- Имена тэгов уникальны без учёта регистра и пробелов по краям. Переименование сохраняет связи с ресурсами и условия сохранённых поисков.
- Одновременно выбирается только один узел панели. Тэги, добавленные через поле поиска, соединяются с условиями выбранного сохранённого поиска оператором «И» и не изменяют сохранённый поиск без явного сохранения. Множественного выбора узлов панели нет.
- Удаление ресурса добавляет «Корзина» и сохраняет остальные тэги. Ресурс с «Корзиной» скрыт из обычных результатов. Восстановление снимает «Корзина».
- Восстановление снимает «Корзину». Если пользовательских тэгов нет, ресурс получает «Входящие»; иначе сохранённые тэги остаются.
- «Входящие» можно назначать и снимать вручную в поле тэгов. «Корзина» там видна, но назначается только через «Удалить» и снимается через «Восстановить».
- Новый ресурс без пользовательских тэгов получает «Входящие». При назначении первого пользовательского тэга «Входящие» снимается автоматически; его можно назначить вручную снова.
- Если у активного ресурса удалён последний пользовательский тэг, «Входящие» назначается автоматически.
- Сохранённый поиск может не иметь обязательных тэгов: он показывает все ресурсы вне Корзины. Такой поиск пользователь может назвать «Все ресурсы».
- Незакреплённый обзор «Все ресурсы» доступен всегда и открывается по умолчанию после запуска. В будущем пользователь сможет назначить стартовый поиск в настройках; эта настройка не входит в первоначальный переход.
- Ручное снятие «Входящих» у ресурса без пользовательских тэгов допускается и не отменяется автоматикой. Автоматическое назначение происходит только при создании, восстановлении или снятии последнего пользовательского тэга.
- При отправке ресурса в Корзину его тэг «Входящие» сохраняется. Сочетание `Корзина И Входящие` допустимо, но обычный поиск «Входящие» исключает ресурсы Корзины.
- Пользовательские поиски можно переставлять выше, ниже и внутрь других поисков перетаскиванием; контекстное меню предоставляет действия перемещения для клавиатуры. Циклы вложенности запрещены.
- Новый поиск создаётся на верхнем уровне по умолчанию; в диалоге можно выбрать родителя. Иконка и цвет имеют значения по умолчанию и редактируются при создании либо позже.
- Поиск с явным условием «Корзина» может сочетаться с другими тэгами и показывает только соответствующие удалённые ресурсы. Если условия «Корзина» нет, удалённые ресурсы скрыты.
- Удаление тэга, используемого сохранёнными поисками, запрещено до удаления его из условий этих поисков; пользователь видит список затронутых поисков.
- Удаление обычного тэга, назначенного ресурсам, после подтверждения снимает его у всех таких ресурсов. Подтверждение показывает число ресурсов; снятие последнего пользовательского тэга у активного ресурса назначает «Входящие».
- Переименование тэга не меняет имя сохранённого поиска, использующего этот тэг.
- Текстовый поиск не сопоставляет имена тэгов: тэги выбираются отдельными чипами. Текст ищется по названию, описанию, адресу и типу ресурса.
- Перетаскивание ресурса на сохранённый поиск назначает все его обязательные тэги, не снимая существующие; перед действием показываются добавляемые тэги. На поиск без условий такое перетаскивание не действует. Перетаскивание на «Корзину» запускает удаление с подтверждением.
- Перетаскивание на составной поиск, содержащий «Корзину», недоступно; для удаления используется обязательный узел «Корзина».
- Повторное перетаскивание ресурса на поиск, все тэги которого уже назначены, не меняет ресурс и даёт короткое уведомление без диалога.

## Устройство прежней реализации

- `Resources.Collection` хранит одно изменяемое имя коллекции.
- «Корзина» сейчас является коллекцией: удаление заменяет прежнее значение `Collection`.
- Боковая панель сейчас представляет плоский список коллекций.
- Существующую пользовательскую базу переносить в новую схему не требуется: владелец приложения согласен начать с пустых данных. При внедрении старую базу следует сохранить как резервную копию с понятным именем и создать новую пустую базу.

## Детали реализации для следующего этапа

- При проектировании схемы и алгоритма поиска проверить составные условия с системными тэгами, пустой поиск, совпадающие имена поисков и отсутствие циклов в дереве.
- При обновлении UI обеспечить понятное исчезновение карточки из результатов после изменения её тэгов, удаления или восстановления.
- Перед созданием новой пустой базы корректно сохранить резервную копию SQLite, включая актуальное состояние базы при используемом режиме журналирования.

## Изменённые решения

- Первоначальное правило «родитель показывает свои и дочерние ресурсы» отменено: дерево имеет только визуальную семантику.
- Первоначальный вариант выбора нескольких узлов панели для поиска «И» отменён: выбирается один узел, дополнительные тэги вводятся в поле поиска.
- Вариант «один тэг — один узел» отменён: узел панели является самостоятельным именованным сохранённым поиском.
- Ранее обсуждавшееся удаление родительского тэга не определяет удаление родительского сохранённого поиска: это разные действия.
- Первоначальная идея перетаскивания ресурса на тэг панели заменена правилами перетаскивания на сохранённый поиск.
- Предыдущее решение о предопределённом тэге «Избранное», звезде и визуальных атрибутах тэгов отменено.
- Первоначальное действие «закрепить тэг из карточки» отменено: поиски создаются только кнопкой у поля поиска.
- Первоначальная потребность в миграции данных коллекций отменена по решению владельца приложения.
